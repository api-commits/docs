The **REST** tab is generated from a snapshot of `openapi/crypto.json` (91 operations). Server: `https://gateway.bit2me.com`.

OpenAPI tags in this snapshot: Access, Wallet, Earn, Account, KYC, Funding, Compliance, Transfers, Market, Loan, Misc.

| Tag | What it is |
| --- | --- |
| Access | HMAC `POST /v1/signin/apikey` (session token for widgets and Pro WS) vs `POST /v1/signin/embed` (embed token exchange — not HMAC API-key sign-in) |
| Market | Wallet catalog (`/v1/currency/…`, `/v2/currency/…`). This is **not** Pro Trading MarketData (`/v1/trading/candle`, `/v2/trading/order-book`) |
| Wallet / Funding | Pockets, transactions, teller deposits, crypto withdrawals |
| KYC / Account / Compliance | Subaccounts, identity, address book, Travel Rule |

Spot trading REST lives under [Pro REST](/pro/rest-overview) (`openapi/trading-spot-rest.json`).

## Playground

Private endpoints require HMAC (`x-api-key`, `api-signature`, `x-nonce`). Mintlify cannot compute that signature. The playground is **simple** (copy the request, sign locally). See [Authentication](/guides/authentication).

Public market helpers on the Wallet spec still need the same client discipline: never paste secrets into the browser.

## Samples

Many operations already ship `x-codeSamples` (Node and curl) from the public spec. Official Pro samples: [trading-spot-samples](https://github.com/bit2me-devs/trading-spot-samples).

The older `bit2me-api-node-tool` repository is discontinued. Cite it only as a historical HMAC helper, not as an SDK.
