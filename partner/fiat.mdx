Fiat collection uses the **Funding / Teller** family. Crypto stays in subaccount pockets until you withdraw on-chain.

<Info>
Check [status.bit2me.com](https://status.bit2me.com) before you debug a timeout or 5xx. If the platform is healthy and the error persists, [open a support ticket](https://support.bit2me.com/en/support/tickets/new).
</Info>

## Prerequisites

1. Parent KYB complete.
2. Subaccount created and, for persons, KYC `verified` / `tier: 2`.
3. Fiat pocket for the currency.
4. `X-SUBACCOUNT-ID` plus HMAC headers.

## Deposit instructions

```http
GET /v1/teller/pocket/reference?pocketId={pocketId}
```

`pocketId` is required. Use this for bank-transfer details tied to a pocket (EUR). Listen for `teller.deposit.transfer.success` and `teller-order-v1`.

## Teller proforma then execute

```http
POST /v1/teller/order/proforma
```

Required: `amount`, `currency`, `orderType` (`deposit` or `purchase`), and `method` as an **object**:

```json
{
  "amount": "10",
  "currency": "EUR",
  "orderType": "deposit",
  "method": { "type": "apple-pay" },
  "destination": { "type": "pocket", "value": "<EUR pocket UUID>" }
}
```

`method.type` enum: `creditcard`, `google-pay`, `apple-pay`, `hub-latam`. That is **not** a string at the `method` key, and it is not `creditCard`.

Proforma **200** is `CreateOrderData` (`orderId` plus amounts and fees). Then execute:

```http
POST /v1/teller/order
```

Body: `{ "orderId": "<id from proforma>" }`. Execute **200** is `ExecuteOrderData`: `status` (including `waiting-user`), `token`, and `provider.requestConfiguration.uri`. Open that URI for the user. See [Apple Pay and Google Pay](/partner/apple-google-pay).

Confirm with `GET /v1/teller/order/status?id={orderId}` and WebSocket `teller-order-v1`. `hub-latam` covers LATAM rails; the snapshot does not name PIX.

## Fiat withdrawals

Fiat out uses Wallet proforma with `destination.bankAccount` on `POST /v1/wallet/transaction/proforma`, then execute. That is **not** the address-book crypto flow and **not** Teller deposit proforma. Follow the Funding / Wallet tags in the [Wallet REST](/wallet/rest-overview) reference for the `bankAccount` object.

USD availability on Wallet is not documented as generally available — confirm with sales if you need USD.
