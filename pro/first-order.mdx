---
title: "First order in minutes"
description: "Place a signed Pro spot order with a known HMAC fixture."
---

<Info>
Check [status.bit2me.com](https://status.bit2me.com) before you debug a timeout or 5xx. If the platform is healthy and the error persists, [open a support ticket](https://support.bit2me.com/en/support/tickets/new).
</Info>

<Steps>
  <Step title="Create a Trade-scoped key">
    Open [Get API keys](https://account.bit2me.com/api-keys). Restrict by IP when you can.
  </Step>
  <Step title="Verify your signer">
    Run the [known-answer fixture](/guides/authentication) before you hit production.
  </Step>
  <Step title="List markets">
    ```http
    GET /v1/trading/market-config
    ```
    Public. Use the returned symbol, min/max, and precision. Sample: [get-markets](https://github.com/bit2me-devs/trading-spot-samples/tree/main/node/rest/market-data/get-markets).
  </Step>
  <Step title="Check ticker or book">
    `GET /v2/trading/tickers` and `GET /v2/trading/order-book`. Still public.
  </Step>
  <Step title="Fund Pro from Wallet">
    Spot orders debit **Pro** balances, not Simple Wallet pockets. Move funds first:

    ```http
    POST /v1/trading/wallet/deposit
    ```

    Required body: `fromPocketId`, `amount`, `currency` (strings). End-user funds: send `X-SUBACCOUNT-ID`. This operation documents **403** (invalid credentials) and **404** (wallet not found), not 412.

    Reverse path: `POST /v1/trading/wallet/withdraw` (`amount`, `currency`, optional `toPocketId`) — next step after the fill.
  </Step>
  <Step title="Place the order">
    ```http
    POST /v1/trading/order
    ```
    Sign `nonce:path:` plus the **exact** compact JSON bytes on the wire (`JSON.stringify` with no spaces). Pro symbols use a slash (`BTC/EUR`), not MCP `BTC-EUR`. Compact body:

    ```json
    {"side":"buy","symbol":"BTC/EUR","price":"50000","amount":"0.01","orderType":"limit"}
    ```

    On this operation, HTTP **412** means price or amount is outside the market min/max from `GET /v1/trading/market-config`. The snapshot does not document **417** here. Wallet **412** (pocket funds) is a different API.

    Sample: [trading-spot-samples REST trading](https://github.com/bit2me-devs/trading-spot-samples/tree/main/node/rest/trading).
  </Step>
  <Step title="Confirm the fill">
    `GET /v1/trading/order/{id}` or subscribe to `my-orders` on the [Pro WebSocket](/pro/websocket).
  </Step>
  <Step title="Return funds to Wallet">
    After the fill, move Pro balances back to a Wallet pocket:

    ```http
    POST /v1/trading/wallet/withdraw
    ```

    Body: `amount`, `currency` (required); `toPocketId` when you target a pocket. Same 403 / 404 as deposit. This is **not** an on-chain withdrawal.

    Wallet → Pro → order → Pro → Wallet is the documented conversion path. Details also sit on the Pro REST **Funding** tag ([Pro REST overview](/pro/rest-overview)).
  </Step>
</Steps>

Amounts are strings. Use `.` for decimals.

Optional: stream fills on `wss://ws.bit2me.com/v1/trading` after [WsAuth](/pro/websocket).
