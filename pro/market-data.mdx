Pro market data is public REST. You do not need an API key for these GETs. Server: `https://gateway.bit2me.com`.

| Need | Call |
| --- | --- |
| Markets | `GET /v1/trading/market-config` |
| OHLCV | `GET /v1/trading/candle` |
| Order book | `GET /v2/trading/order-book` |
| Tickers / last trades | MarketData tag in the [Pro REST](/pro/rest-overview) reference |

Official sample: [get-ohlcv](https://github.com/bit2me-devs/trading-spot-samples/blob/main/node/rest/market-data/get-ohlcv).

Check [status.bit2me.com](https://status.bit2me.com) before you debug empty candles or 5xx. If the platform is healthy and this persists, [open a support ticket](https://support.bit2me.com/en/support/tickets/new).
</Info>

## Candle intervals (Pro)

`GET /v1/trading/candle` requires `symbol`, `interval`, `startTime`, `endTime`, and `limit`. `startTime` / `endTime` are Unix time in **milliseconds**. OpenAPI `interval` is **minutes**:

| `interval` | Meaning |
| --- | --- |
| `1` | 1 minute |
| `5` | 5 minutes |
| `15` | 15 minutes |
| `30` | 30 minutes |
| `60` | 1 hour |
| `240` | 4 hours |
| `1440` | 1 day |

The last entry in the array is the **current** (in-progress) candle. OpenAPI documents `limit` with a maximum of **1000**.

Page with a new `startTime` / `endTime` window if you need more history than one response. Do not invent extra caps.

Wallet Market catalog (`GET /v3/currency/ticker/{symbol}` and named intervals such as `one_hour`) is a **different** HMAC surface under Wallet REST **Market**. Do not mix those interval names with Pro `GET /v1/trading/candle`.

## Live book and trades

For a streaming book and public prints, use [Pro WebSocket public channels](/pro/websocket-public) (`order-book`, `public-trades`). REST candles are for history and charts.
